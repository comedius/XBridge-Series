## 1. Legend and counting rule

- `documented (project-authored)` — One row means one distinct requirement derived from the supplied reports or the repository baseline; statuses are package workflow classifications, not capability-status tokens (`docs/RESEARCH_REGISTER.md:27-37`; `docs/AGENT_TASKS.md:4097-4099`).

- `documented (project-authored)` — `implemented` requires completed Xbox-facing behavior in cited repository evidence; none of the 44 rows meets that threshold (`README.md:5,9-14`; `docs/ARCHITECTURE.md:63-69`).
- `documented (project-authored)` — `partial` means a generic, synthetic or read-only seam exists but does not supply the named Xbox-facing requirement; `planned` means repository documents record only a direction or research lead (`docs/ARCHITECTURE.md:54-61`; `docs/architecture/XB_NEXT_03_EXECUTION_STRATEGY_DRAFT.md:31-35,43-61`).
- `documented (project-authored)` — `missing` means no cited repository source supplies the named behavior; `unknown` means the available report and repository evidence is insufficient to classify the requirement (`docs/RESEARCH_REGISTER.md:18-37`; `include/xbridge/analysis/game_intelligence.hpp:24-30,53-60`).
