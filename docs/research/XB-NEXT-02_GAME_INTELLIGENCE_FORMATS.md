## 2. Confirmed PE/COFF facts (readable metadata)

All rows in this section are `documented (authoritative)` from S1 unless stated otherwise. These are **general Windows PE/COFF facts**, not Xbox Series X behavior.

| # | Finding | Label / source |
|---|---|---|
| P01 | DOS header contains `e_magic` = `0x5A4D` (`MZ`) and `e_lfanew`, the file offset of the PE header; the PE specification places the PE-signature offset at file offset `0x3c`. | `documented (authoritative)` S1, S2 |
| P02 | The PE image signature is the 4 bytes `PE\0\0` at the offset from P01; the MS-DOS stub precedes it. | `documented (authoritative)` S1 |
| P03 | COFF header, relative to its start: `Machine` (offset 0, 2 bytes), `NumberOfSections` (2, 2), `TimeDateStamp` (4, 4), `PointerToSymbolTable` (8, 4), `NumberOfSymbols` (12, 4), `SizeOfOptionalHeader` (16, 2), `Characteristics` (18, 2). | `documented (authoritative)` S1 |
| P04 | `NumberOfSections` determines the size of the immediately following section table; the Windows loader limits sections to 96. | `documented (authoritative)` S1 |
| P05 | A `TimeDateStamp` value of `0` or `0xFFFFFFFF` does not represent a meaningful date/time; `IMAGE_DEBUG_TYPE_REPRO` may replace stamps with hash bits. | `documented (authoritative)` S1 |
| P06 | Optional-header `Magic`: `0x10b` = PE32, `0x20b` = PE32+, `0x107` = ROM image. PE32+ allows a 64-bit address space while limiting image size to 2 GB. | `documented (authoritative)` S1 |
| P07 | Standard fields: `AddressOfEntryPoint` at optional-header offset 16 (RVA from image base; zero is valid when no DLL entry point); `BaseOfCode` at 20; PE32 alone has `BaseOfData` at 24. | `documented (authoritative)` S1 |
| P08 | Windows-specific fields include `ImageBase` (offset PE32/PE32+ 28/24; 4/8 bytes; multiple of 64 K), `SectionAlignment`, `FileAlignment`, `SizeOfImage`, `SizeOfHeaders`, `CheckSum`, `Subsystem` (68/68), `DllCharacteristics` (70/70), `NumberOfRvaAndSizes` (92/108). | `documented (authoritative)` S1 |
| P09 | Data directories begin at optional-header offset 96 (PE32) / 112 (PE32+); each is 8 bytes: `VirtualAddress` (an RVA) and `Size` in bytes. Indices: 0 Export, 1 Import, 2 Resource, 3 Exception, 4 Certificate, 5 Base Relocation, 6 Debug, 12 IAT, 13 Delay Import. The Certificate Table's first field is a **file pointer**, not an RVA. | `documented (authoritative)` S1 |
| P10 | The section table has no direct pointer in the file header; it starts after the optional header using the COFF `SizeOfOptionalHeader`. Each 40-byte entry has `Name` (8 bytes), `VirtualSize`, `VirtualAddress`, `SizeOfRawData`, `PointerToRawData`, pointer/count fields, and `Characteristics`. | `documented (authoritative)` S1 |
| P11 | File `Characteristics` flags include `RELOCS_STRIPPED 0x0001`, `EXECUTABLE_IMAGE 0x0002`, `32BIT_MACHINE 0x0100`, `DEBUG_STRIPPED 0x0200`, `DLL 0x2000`; section flags include `CNT_CODE 0x20`, `MEM_EXECUTE 0x20000000`, `MEM_READ 0x40000000`, `MEM_WRITE 0x80000000`. | `documented (authoritative)` S1 |
| P12 | `DllCharacteristics` flags include `HIGH_ENTROPY_VA 0x0020`, `DYNAMIC_BASE 0x0040`, `FORCE_INTEGRITY 0x0080`, `NX_COMPAT 0x0100`, `NO_SEH 0x0400`, `APPCONTAINER 0x1000`, `GUARD_CF 0x4000`. These are loader/runtime assertions, not proof of host compatibility. | `documented (authoritative)` S1 |
| P13 | The specification explicitly warns that it is `not guaranteed to be a complete specification in all respects` and that `SizeOfOptionalHeader` and `NumberOfRvaAndSizes` must bound directory probes. | `documented (authoritative)` S1 |
| P14 | Existing project documentation records prior Zen 2 / D3D12 / memory / storage / service claims as project-authored and leaves Xbox guest-visible details unknown; no prior entry establishes a Series X game-file format. | `documented (project-authored)` S12 |

## 4. Import, export, relocation, debug and resource facts

### 4.1 Enumeration procedures (documented structures)

| # | Finding | Label / source |
|---|---|---|
| D01 | Import directory: array of 20-byte descriptors, each with `Import Lookup Table RVA`, `Time/Date Stamp`, `Forwarder Chain`, `Name RVA` (DLL name), `Import Address Table RVA`; the array ends with an all-null descriptor. | `documented (authoritative)` S1 |
| D02 | Import lookup table entries are 32-bit in PE32 and 64-bit in PE32+; the top bit selects import-by-ordinal, bits 15–0 hold the ordinal, and the remaining low bits hold a hint/name-table RVA; a zero entry terminates the table. | `documented (authoritative)` S1 |
| D03 | Hint/Name entry: 2-byte `Hint`, then a case-sensitive null-terminated ASCII import name, plus optional even-boundary pad byte. DLL names and export names are ASCII strings referenced by RVA. | `documented (authoritative)` S1 |
| D04 | Export directory (40 bytes) supplies `Name RVA`, `Ordinal Base`, `Address Table Entries`, `Number of Name Pointers`, `Export Address Table RVA`, `Name Pointer RVA`, `Ordinal Table RVA`. | `documented (authoritative)` S1 |
| D05 | Export address table entries are either export RVAs or forwarder RVAs; a forwarder string must lie inside the export table range given by the data directory. Name-pointer and ordinal tables are parallel arrays; ordinals are 16-bit and `Ordinal Base` must be subtracted. Name pointers are lexically sorted; export names are null-terminated ASCII strings. | `documented (authoritative)` S1 |
| D06 | Base relocation directory is divided into per-4K-page blocks on 32-bit boundaries. Each block starts with `Page RVA` and `Block Size`; entries are 16-bit words with a 4-bit type and 12-bit offset. `ABSOLUTE = 0` is skipped; `DIR64 = 10` applies to a 64-bit field; `HIGHADJ = 4` occupies two slots. | `documented (authoritative)` S1 |
| D07 | Debug directory is an array of 28-byte entries (`Characteristics`, `TimeDateStamp`, `MajorVersion`, `MinorVersion`, `Type`, `SizeOfData`, `AddressOfRawData`, `PointerToRawData`). It may reside in a discardable `.debug` section, another section, or no section. `AddressOfRawData` may be zero when the data is not mapped. Types include `CODEVIEW = 2`, `REPRO = 16`, `EX_DLLCHARACTERISTICS = 20`. | `documented (authoritative)` S1 |
| D08 | Resource directory (`.rsrc`) is a binary-sorted tree conventionally ordered Type → Name → Language: 16-byte table headers, 8-byte entries using high-bit `0` for data and `1` for subdirectory, word-aligned Unicode name strings, and 16-byte resource data entries (`Data RVA`, `Size`, `Codepage`, reserved). The specification documents these fields but not resource payload semantics. | `documented (authoritative)` S1; payload semantics `unknown` |

### 4.2 Strict-bounds requirements and malformed-file risks

| # | Finding | Label / source |
|---|---|---|
| B01 | Required by the specification: bound each directory probe by `SizeOfOptionalHeader` and `NumberOfRvaAndSizes`; do not assume directory RVAs point to section starts or that tables have conventional section names. | `documented (authoritative)` S1 |
| B02 | A safe analyzer should treat all offsets, counts and string walks as untrusted: check `e_lfanew` and full header extent against file length; check `NumberOfSections × 40` against file length; check `PointerToRawData + SizeOfRawData` with overflow-safe arithmetic; cap descriptor/thunk/entry counts by the corresponding data-directory `Size` or section extent before any loop; terminate string scans strictly at the bounded region end. | `hypothesis` (engineering inference from S1 constraints; no implementation by this package) |
| B03 | RVA-to-file-offset mapping must be derived from the section table with explicit containment and overlap checks; multiple or overlapping sections, a zero-size directory with nonzero RVA, a missing null terminator, a null descriptor omitted, a truncated relocation block, an unbounded forwarder string, or a debug `PointerToRawData` beyond EOF are malformed-file risks. | `hypothesis` (engineering inference; `documented (authoritative)` S1 for the underlying fields) |
| B04 | `Block Size` must be at least 8, fit entirely in the relocation directory, and leave an even number of entry bytes; machine-specific relocation types must be interpreted consistently with `Machine`. | `hypothesis` (engineering inference; `documented (authoritative)` S1 for block/type definitions) |
| B05 | The certificate directory is a file offset rather than an RVA; applying RVA mapping to it would misread the file. Forwarder strings must be confined to the export directory range, and the `0`/`0xFFFFFFFF` timestamp values must not be reported as dates. | `documented (authoritative)` S1 |
