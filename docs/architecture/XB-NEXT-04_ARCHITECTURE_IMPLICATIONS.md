## 3. Boundary and ADR risk classes

`documented` — Loader and memory rollback are a boundary risk: physical backing cannot be removed or permission-mutated through the current API, so the loader records an inaccessible marker instead (`include/xbridge/loader/executable_loader.hpp:35-41`; `src/loader/executable_loader.cpp:88-111`; `include/xbridge/memory/guest_physical_memory.hpp:18-35`). This is not fixed by this documentation package.

`documented` — Backend policy has two distinct layers: internal synthetic routine selection uses `ExecutionBackendPreference` / `ExecutionBackendKind` (`include/xbridge/execution/native_execution_backend.hpp:74-91`), while public `ExecutionPolicy` still exposes JIT-oriented `CpuBackend` and `CpuPreference` values (`include/xbridge/host/execution_policy.hpp:7-17`). The execution-strategy draft explicitly leaves user-facing backend policy open (`docs/architecture/XB_NEXT_03_EXECUTION_STRATEGY_DRAFT.md:69`).

`documented` — Arbitrary native guest-code isolation is unresolved. The native backend accepts only compiled-in routines (`include/xbridge/execution/native_execution_backend.hpp:10-12`), the draft leaves isolation open (`docs/architecture/XB_NEXT_03_EXECUTION_STRATEGY_DRAFT.md:41,68`), and prior analysis does not establish Job Objects, restricted tokens or AppContainer alone as a complete security boundary (`docs/research/XB-NEXT-03_NATIVE_EXECUTION_FEASIBILITY.md:64-73`).

`documented` — Runtime service mapping remains a research indicator only: four library-family names are mapped to neutral service tokens, explicitly labeled `Indicator`, and marker interfaces define no Xbox behavior (`src/analysis/game_intelligence.cpp:94-142`; `include/xbridge/runtime/system_services.hpp:7-9,45-113`).

`documented` — Graphics is an ADR risk because ADR-0007 requires separation of guest interpretation, resource/synchronization modeling, shader IR and host backend (`docs/DECISIONS.md:33-36`; `docs/ARCHITECTURE.md:231-233`); D3D12.X equivalence is `unknown`, not accepted (`docs/architecture/XB_NEXT_03_EXECUTION_STRATEGY_DRAFT.md:61`).

`documented` — Containers are a module and legal boundary: the analyzer only weakly labels `.xvc` / `.msixvc` and does not inspect payloads (`src/analysis/game_intelligence.cpp:85-87,253-259`), while new dependencies, protected content and DRM work are forbidden without separate approval (`AGENTS.md:37-43,98`; `docs/AGENT_TASKS.md:4098`).

`documented` — The development/product boundary is unchanged. Research documents, agent prompts, workflow material, task ledgers and this implications file stay in the public development repository but must not be copied automatically into a future product package (`docs/AGENT_WORKFLOW.md:76-90`; `docs/ARCHITECTURE.md:251-253`).
